# 文件、目录与用户数据

用于判断陌生目录、安装目录、用户配置、共享组件及卸载后的文件残留。
已安装软件优先使用对应正式卸载入口，再依据卸载前记录检查剩余文件。

## 先确定对象性质

| 对象 | 需要回答的问题 | 处理影响 |
| --- | --- | --- |
| 程序文件 | 属于哪个安装实例，是否仍被入口调用 | 软件或部分功能不可用 |
| 配置与工作状态 | 是否包含账号、扩展、配置、会话、授权数据 | 重装软件未必能恢复原状态 |
| 缓存 | 是否确实可由仍存在的程序和来源重新生成 | 可能重新下载，离线内容未必可恢复 |
| 用户资产 | 是否为项目、虚拟机、存档、备份、安装包或资料 | 程序重装无法恢复这些资产 |
| 共享组件 | 哪些软件引用其中哪些文件 | 可能同时影响其他软件 |
| 历史痕迹 | 只是记录曾经运行，还是有效入口 | 历史文本通常不会启动程序 |

文件夹名称、大小、时间戳、签名分别是线索，任何一个都不能独立证明可删除。
签名相同可能只说明同厂商；名称相同或功能相似也可能来自不同厂商。
安装包在用户资料库中是资产；本任务下载并临时使用的安装包是任务临时文件。

上述分类用于组织取证。向用户解释时，按 [对象审查](../audit.md) 继续说明具体归属、实际功能与使用关系；不能只把“缓存、配置、工作状态”等分类作为用途结论。即使文件较小或目录为空，用户关心的来源问题仍需按其对决策的影响处理。

## 有限概览与身份确认

父目录批量审查先按 [系统项筛选](../system-exclusions.md) 处理默认范围。仅因隐藏或系统属性不能排除对象；应用数据与用户资料保留入口。默认排除项的元数据只用于范围判断和计数，正式入批后再适用完整五项审查。

先查看指定目录直接内容，再沿当前对象的证据展开；不从一个命中项扩展到全盘搜索。
候选复杂目录按批量规程交还用户选择展开，不能用递归概览替代规定的分批审查。

```powershell
# $targetPath 是本轮已定位的目录。
Get-Item -LiteralPath $targetPath -Force -ErrorAction Stop |
    Select-Object FullName, Attributes, LinkType, Target, LastWriteTime
Get-ChildItem -LiteralPath $targetPath -Force -ErrorAction Stop |
    Select-Object Name, PSIsContainer, Length, Attributes, LastWriteTime
```

可执行文件的版本与签名只读取已定位文件，不运行未知程序来获取版本。

```powershell
# $binaryPath 是已定位的具体文件。
$binary = Get-Item -LiteralPath $binaryPath -ErrorAction Stop
$binary.VersionInfo | Select-Object ProductName, CompanyName, FileDescription, FileVersion
Get-AuthenticodeSignature -LiteralPath $binary.FullName |
    Select-Object Status, StatusMessage, SignerCertificate
```

继续对照卸载登记、当前进程路径、启动入口、同目录主程序、配置中的产品名与日志域名。
无签名不等于异常，签名有效也不代表用户仍需要该软件。
读取日志优先提取产品信息、路径及调用关系，不向报告复制令牌、账号或无关内容。

## 共享目录与第二份部署

`SDK`、`Runtime`、`Common`、厂商目录不是自动保留整包或自动删除整包的依据。
保留要求约束写操作；在本轮审查范围内仍应检查共享目录内容与外部引用。
逐层辨认可执行文件、更新器、脚本、配置与日志，形成组件级归属，而非只有目录级归属。

发现一个组件后，按以下关联继续检查：

1. 从正在运行的路径、服务、计划任务参数查出实际使用的副本。
2. 对照已知安装目录、共享数据目录与任务引用目录，寻找第二份部署。
3. 用文件名、产品信息、版本、签名和历史安装路径验证是否同一组件。
4. 查明更新器是否会重新写入载荷；仅移除主目录不能证明更新链已消失。
5. 分别记录可删除组件、其他软件仍使用的组件与归属未定内容。

例如主安装目录已删除，但共享目录中的更新器仍由系统目录下的脚本拉起，
应在同一引用链中检查载荷、更新器和脚本；同厂商另一款有效软件独立保留。
AppCompat 等历史运行路径可协助归因，但不能当成当前仍在运行的证据。
具体持久化追踪见 [启动与后台组件](startup-runtime.md)。

## 用户资产与数据边界

- 虚拟机磁盘、快照、配置和日志共同构成虚拟机资产；文件名含厂商名不改变其性质。
- 游戏客户端、游戏库、官方存档、第三方模拟器存档分别归组；数字目录可进一步映射游戏身份。
- 编辑器的用户级扩展与配置不同于项目内配置；不能按 `.vscode` 等名称遍历删除项目内容。
- 源码、构建材料、学习资料、安装包及备份不因引用已卸载程序就失去资产性质。
- 授权运行时的数据可能位于系统账户配置目录，重新安装运行时不保证恢复授权。
- 包含账号或设置的目录不得仅凭 `Cache`、`Temp`、`Saves` 等名称决定处理方式。

复查保留资产时以既有清单和实际操作范围为依据，不额外遍历全部资产或生成哈希材料。

## 目录处理与复查

普通文件使用通用规程规定的回收站优先方式；受保护组件先走正式卸载机制。
对存在链接或重解析点的目标，核对链接本身与实际指向；不得自动跟随到范围外目录。
访问被拒绝、离线盘、网络不可达与路径不存在是不同结果，不能统一标为不存在。
只读属性或权限问题不能单独证明需要接管所有权；先定位具体阻塞对象及其仍在使用的原因。

复查应回答：

- 指定文件或目录是否按实际处理方式离开原位置。
- 已发现的其他部署、进程和启动引用是否仍指向该组件。
- 保留的共享内容及资产是否仍在预期范围内。
- 已卸载目录中的新文件、下载器或更新器是否表明存在未处理的重建来源。
- 本任务临时工具是否已处理；移入回收站后空间是否仍待清空回收站才释放。

“文件已消失”只能说明该路径的状态；结论必须限定到已审组件与已查引用。
